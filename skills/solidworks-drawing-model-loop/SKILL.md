# SolidWorks 图纸建模闭环

汇集 SOLIDWORKS 2026（Revision 34.0.0）图纸建模与 2025 SP5（Revision 33.5.0）已有装配参数化经验。其他版本重新核对接口和模板；本机路径、语言、PID、案例尺寸不是固定配置。

## 连接与目标身份

- 优先连接当前会话。`GetActiveObject('SldWorks.Application')` 失败不代表程序未运行；枚举 ROT 的 `SolidWorks_PID_<pid>` 并绑定。多实例先定位，不取第一个实例盲写。
- 用 [scripts/sw_probe.py](scripts/sw_probe.py) 只读盘点实例/文档。该脚本不启动、激活、重建或保存 CAD。
- 修改前记录目标路径、名称和类型。已有文件按完整路径重取；新文件保留创建返回对象，跨脚本恢复时核对身份。不要在导入模块时直接修改 `ActiveDoc`。
- 按用户目标区分零件、多实体零件、装配体和钣金。多实体零件不等于带配合的装配体，有特征树不等于可展开钣金。

## 图纸、参数与小案例

- 渲染图纸并放大关键尺寸，文字提取只辅助定位。分清明确尺寸、视图解释和未标注假设。影响主要结构的缺失尺寸需澄清；可继续的局部外观假设写入说明。
- 提取壁厚、标高、内/外径口径、孔径/数量/分度圆、角向位置；明确基准、单位和部件依赖后建模。
- 使用同一组命名参数驱动几何，并回读关键输入。可记录 `DrawingNumber`、`MaterialSpec`、`SHELL_ID_MM`、`WALL_MM` 等属性。
- 全局变量只有链接到草图/特征尺寸才会自动驱动。仅记录变量时，不宣称已完全参数联动。参数测试需验证修改值确实改变实际几何，并在恢复默认值后再次回读；非活动文档出现更新停滞时先激活并重新绑定目标。
- 先在新目标或专用测试文件建立一个真实基本特征，如锥壳；回读实体数量、正体积和关键几何再继续。失败时检查半成品，避免反复新建无法追踪的空文档。

## 建模中的关键检查

已有多实体零件在大幅改尺寸后出现分割、裁剪或下游连锁错误时，读 [references/split-body-parametric-repair.md](references/split-body-parametric-repair.md)。优先定位首个错误和保留/消耗实体身份；不要以放宽尺寸容差替代拓扑修复。

### 已有装配体的参数化

此类任务先读 [references/parametric-assembly.md](references/parametric-assembly.md)，尤其是“数量改了尺寸不变”、多种孔组、拆实体装配或跨文件联动。

涉及从总装提取独立系统、内板/保温/外包板分层、保留附件及中文参数面板交付时，另读 [references/insulated-system-extraction.md](references/insulated-system-extraction.md)。重点是实体身份、法向厚度、保温开口、版本提交与实际入口验收；案例尺寸不作为新项目默认值。

涉及进风头部与塔体共体截取、CadQuery 分层重建、STEP 导入模板/材质异常时，再读 [references/inlet-head-import-loop.md](references/inlet-head-import-loop.md)。其中区分几何引擎往返、原生回读和面板验收，防止把不同层级的证据混用。

- 先把用户术语映射为明确的轴、中心距/净间隙、每边/总孔数和下游尺寸链。不能只把数值写入全局变量或属性。
- 数量变化涉及外形时，从原模型推导端部余量，联动箱体、板、夹层、罩及接口位置；用真实数量变更验证外形。保留整体厚层不等于已建立金属板厚，未确认值单独标记。
- 脚本驱动、固定组件定位和后台同步要如实说明。对用户实际使用的入口做一次端到端测试；只跑内部更新函数不能证明方程界面会联动。
- 沿用成熟零件，按依赖边界拆分必要实体。对源文件做哈希保护，保存后的输出装配回读所有引用路径。

涉及独立设备外形、整机布局、风管/框架联动和中文参数面板时，读 [references/envelope-layout-parametric.md](references/envelope-layout-parametric.md)。该模式保留源未保存状态、采用版本化提交，并分别验证真实几何与用户入口。

使用 COM 建模前读 [references/com-geometry.md](references/com-geometry.md)，包含兼容模式和本机验证的方向处理。

涉及等面积进出口、偏心斜切、可调方位角或旋风派生装配时，另读 [references/cyclone-parametric-loop.md](references/cyclone-parametric-loop.md)，其中区分通用方法与R4案例尺寸。

涉及 DXF 图块、旋转座体/锥壳或新旧组件对接时，读 [references/seat-assembly-loop.md](references/seat-assembly-loop.md)，重点处理活动文档参数回读、无顶点旋转体、总装干涉和 STEP 模板弹窗。

涉及保温多层壳体、顶盖与筒壁焊接、穿保温接管或旧参数面板升级时，读 [references/layered-roof-weld-joints.md](references/layered-roof-weld-joints.md)。先区分结构连接方式与文件拆分方式；不得从独立零件边界推断必须增加法兰。该参考也说明当前版本、历史验收和固定导出文件可能不同步时的核对方法。

- 旋转类零件可采用闭合剖面与中心线。法向板厚与径向差不同；分别判断真实几何。
- 不猜本地化基准面名及正负方向。读取草图变换，首个附件生成后核查位置。
- 起始偏移与拉伸/切除方向分别验证；修正一个不代表另一个正确。
- 孔组限定深度或作用实体。出口法兰“贯穿全部”可能误伤下方锥壳和顶盖，检查受影响实体、解析面与体积变化。
- 切向接管检查圆弧接合、开口方向和流道连通；外观贴合不足以证明连通。
- 分别定义侧出方式、周向方位角、轴线偏心；不能用方位旋转代替偏心接出。明确“容差”指验收误差、板厚还是装配间隙，不把三者共用为一个变量。
- `GetBodyBox()` 为近似包围盒，只用于粗查轴向、数量级及位置。精确尺寸使用特征参数、草图尺寸或解析面，不能用包围盒验收制造公差。
- 修正本次创建且身份明确的特征；删除失败特征时确认从属草图与依赖，避免孤立可见草图及误删。

## 材料、验证和保存

- 在本机实际 `.sldmat` 查准确名称，赋材质后通过 `IPartDoc.GetMaterialPropertyName2` 回读。写入 `MaterialSpec=316L` 不等于实体已赋材质。
- 完整重建后检查实体数、体积、关键尺寸、接口、孔组和特征错误。需要时遍历子特征；只检查顶层时明确范围。
- 对不应改变的实体检查不变量，例如出口法兰打孔前后锥壳体积应不变。正体积和零错误不证明无干涉、无重复实体或可制造。
- 回归包含用户报告的失败尺寸，在相关工况逐一检查几何与干涉。角度联动用实际轴线、点坐标或方向极值验证，体积不变不能检验刚体旋转。改方程式前激活并重新绑定目标文档，证明几何真的变化后再检查派生组件。
- 首个小案例包含用户实际目标值；默认值附近的小幅 A→B→A 仅证明局部可用。故障定位先验证首个失效特征及其直接几何，修复后再运行受影响回归和交付检查，避免每次探测都重建面板、导出 STEP 或跑完整测试集。记录分阶段耗时后再判断瓶颈，不把 COM、内核或后台窗口速度当作未经测量的结论。
- 保存原生文件；需要交换格式时导出 STEP。记录返回值、错误码、警告码并检查文件存在。新交付避免覆盖旧文件。
- 重开验证仅针对已保存、身份明确的输出；不要关闭用户未保存文档。比较实体数、体积、材料、关键属性，采用合理数值容差。
- 进程退出先检查会话与已保存产物；任务仍要求操作时可恢复一次。不要无限重启或把未知退出原因宣称为崩溃。
- 用可用桌面截图工具或 SolidWorks `SaveBMP` 检查能看清主要接口的视图。最终交付文件链接、验证结果和未解决尺寸。

## 只读探测脚本

使用已安装 pywin32 的 Python，替换实际路径：

```powershell
python <skill-dir>/scripts/sw_probe.py
python <skill-dir>/scripts/sw_probe.py --pid <observed-pid> --document <absolute-open-part-path> --tlb <installed-sldworks.tlb> --output <new-report.json>
```

无 `--document` 时只盘点；指定文档时只快照已打开零件。多实例必须指定 PID。`--tlb` 从当前安装类型库生成 pywin32 包装缓存，读取材料和顶层特征状态；不提供时报告这些检查不可用，不当作通过。报告文件拒绝覆盖。

只在需要历史案例时读 [references/xf-case.md](references/xf-case.md)，不要移植其中未标尺寸的假设。
