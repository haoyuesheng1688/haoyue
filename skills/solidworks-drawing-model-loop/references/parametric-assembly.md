# 已有装配体参数化：定义、联动、验收与避坑

适用于已有加热器、箱体、阵列安装板及类似装配。依据 LPG-25 在 SOLIDWORKS 2025 SP5 的实测经验；案例路径和尺寸不能直接推广到其他模型。

## 先定参数语义与依赖链

建立“用户词语 → 实际几何 → 参数 → 下游对象 → 验证量”映射。

- “间距”可能是相邻错列步距、同排中心距或净间隙；不能直接套阵列显示的间距。
- “接口孔距”可能是电热管两个端部中心距、风道法兰孔距或盖板连接孔距。先识别图中或实体中的孔组。
- 每边孔数包含角孔时，矩形周边唯一孔数为 `2*N_long + 2*N_width - 4`。先布置两条完整对边，再补另外两边的中间孔；不要重复四角。
- 长向/宽向绑定稳定的设计轴，不按当前包围盒哪一边更长动态互换。否则改变数量跨过长宽临界点会颠倒参数含义。
- 用户把每支功率定义为常数时，`P_total = N*P_unit` 是该产品输入约定，不是电热丝长度、电阻和热负荷的自动计算。

数量应如何影响外形是设计意图。若需保持两端余量，取原始跨度 `(N0-1)*S0`，推导 `M = L0 - (N0-1)*S0`，再用 `L = M + (N-1)*S`。同时更新开口、安装板、夹层、罩、孔组原点及端部法兰位置，不能只移动管阵列。

未定义的金属板厚可留空并说明不驱动实体。不得把源模型中代表整个夹层的厚实体解释成金属板厚；用户允许拆分也不代表可以凭空确定内外板厚。

## 原生特征与脚本的边界

优先保留已有可靠特征，补充方程和必要的局部重构。可以采用“原生方程 + 有界脚本更新”的混合方案，但要说明：

- 原生尺寸/阵列方程可在 SolidWorks 重建时求解。
- 写入同名全局变量并不会自动重画孔组、生成组件或改变扫描路径。
- 脚本重建组件并固定变换，不等于原生配合驱动装配；重建会改变组件实例标识，可能使用户后来添加的配合失去引用。
- 保留草图特征对象，替换其中几何，在此案例保持了扫描/切除的上游引用。这是经过实测的局部策略，不是任意草图都能安全替换。检查被删尺寸、外部引用、下游附着面及特征状态。

拆分时尽量按法兰、夹层、安装板等依赖边界分文件。同一法兰零件可重复引用。不要把一次性探测脚本复制成通用自动化入口：历史脚本可能在 import 时操作旧路径、旧 PID 或未保存文档。

## COM 实测问题

|现象|此次处理及适用边界|
|---|---|
|全局变量 Add2 成功，尺寸方程 Add2 返回 -1|先激活已核对路径的目标文档再添加；在本机解决。失败后逐条核对方程、尺寸全名和返回索引，不当作已关联|
|无参方法结果被当作函数再次调用，报“找不到成员”|使用 com-geometry.md 中的 value 辅助函数，若返回 COM 对象直接使用；如 CreateSelectData、GetMathUtility|
|动态/类型化 Select2、Select4 的空对象参数报类型不匹配|查实际包装签名。动态调用曾需 VT_DISPATCH 空 VARIANT；类型化 IComponent2/IBody2 接口使用 None。不要全局替换一种写法|
|OpenDoc6、SaveAs 返回值或输出参数不匹配|在适用的动态接口显式传入 BYREF I4 错误/警告变量；保存成功、错误码、文件存在和重开是不同证据|
|动态 MathUtility.CreateTransform 出错|本机通过 IMathUtility 类型包装和 VT_ARRAY\|VT_R8 的16元素变换数组解决|
|GetPackAndGo 调用失败|此次转用复制文件及 ReplaceReferencedDocument 修改未打开的输出装配，再打开回读引用。不能据此认定 SolidWorks 不支持 Pack and Go|
|文件夹里残留原型装配和 ~$ 锁文件|最终链接明确指向交付装配；ZIP 排除锁文件及原型，做 CRC 检查|

## 自动同步的运行条件

如果采用本地后台 COM 同步器，让用户知道它不是 SolidWorks 内置功能，也不是“修改变量就永远自动更新”。交付启动、停止入口与可读状态。

- 同步器只绑定目标实例和完整文件路径。读取实际主装配方程，不让旧 JSON 覆盖用户刚在 SolidWorks 输入的数量。
- 明确输入优先级。方程未变而用户正在改 JSON 时，不能把旧方程值反写覆盖 JSON。
- 对稳定输入做一次同步，防抖；更新中串行写 CAD，维护已应用签名，避免自身回写形成无限循环。
- 验证全部成功后才提交新的已应用参数记录。失败输入签名暂时阻断，直到用户修正或显式重试；保存可恢复副本。
- 当前案例解析的是纯数值输入，不支持在受监控输入字段随意填表达式或任意单位文本。不要宣称比实现更多的能力。
- COM 忙/方程对话框未关闭与 RPC 断开不同。前者有限重试；SolidWorks 已关闭、旧对象报 `-2147023174` 时结束该会话的同步或重新只读探测并校验身份，不永久吞错重试。重连后先核对文档，不能把未完成写入自动重放到别的模型。
- 辅助进程隐藏启动，提供项目本地停止信号；更改脚本后现存进程仍使用旧模块，需在空闲状态重启再验证。

后续发现：本案例同步器在 SolidWorks 关闭后仍重复报告 RPC 不可用。知识沉淀时已发出停止信号；原代码的异常分类/自动退出仍是改进项，不能说已实现自动重连。

## 验收选择与证据分层

先做小案例，再验证真实入口，避免只证明内部函数可用：

1. 记录基准尺寸、孔组、组件数量、源文件哈希和实际参数。
2. 单一参数往返，例如法兰厚6→8→6 mm；回读尺寸和实体体积。
3. 改数量，检查外形和所有相关部件一起变化；奇偶数量都覆盖，安装孔与端部对应。
4. 改孔数，回读实体的圆柱孔面及中心布局，而不只数草图圆或方程值。核查角孔去重、边距、孔径及作用范围。
5. 通过用户使用的入口修改主装配方程，证明后台同步/宏确实运行；仅测试 Python run() 不算方程入口验收。
6. 恢复用户当前值，保存后关闭本次输出并重开；核对引用路径、参数、体积和检查结果。不要恢复成早期默认值而覆盖用户的新输入。

`GetBodyBox` 是近似检查，不能拿极小比较阈值当作制造精度证明。需要严格公差时用尺寸、解析面或极值接口。体积守恒是拆分基准的检查，改了箱长后不能再要求与原模型体积相等。

顶层零错误、正体积、抽样孔位一致、STEP 导出成功，分别报告。它们都不单独证明全装配无干涉、金属材料正确或制造图验收。2 mm几何比对容差不自动成为加工公差。
