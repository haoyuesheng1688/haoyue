# 独立系统提取、保温分层与面板交付

适用于从多实体源零件/装配提取局部系统，再建立可调板厚、保温、接口与附件的独立交付。依据 PPG-25 底部在 SolidWorks 2025 SP5 的实测；尺寸、实体数量、坐标和容差须由当前任务重定。

## 识别与依赖边界

- 在源只读盘点中同时记录完整文档路径、配置、未保存状态、文件哈希、组件变换。哈希只证明磁盘文件未变，不能证明未保存的内存模型未变；未保存状态单独记录，不自动保存或关闭源。
- 用实体身份/持久引用配合解析几何、空间位置、体积确定范围，不能依赖 GetBodies2 枚举顺序。相同体积不能唯一标识实体；实体改名后重新匹配。
- 先保存原形基准，再按主体、法兰、接管、保温、外包和附件依赖分件。记录原形与重建模型的几何差异，不把去圆角的重建件称为完全同形复制。
- 实体提取前后核对数量、逐体体积、位置与接口。重建后因分层、开孔或新增适配件而增加的实体要单独解释，不能继续要求与源总数相等。
- 成熟附件优先保留原生几何；仅为简化代码而 STEP 往返可能引入修复差异。所有引用须在交付范围内；保存重开后遍历验证真实引用路径与文件存在。

## 参数语义与三层几何

- 明确固定接口基准、向下/向外正方向、角度零向及正向。将“外排出口”落实到指定轴线，避免混淆侧排和底排。
- 内径不变时，圆柱外径随板厚增量变化两倍。锥段各层按剖面法向偏移并求相邻偏移线交点，不能把统一径向增量当作法向板厚。偏移后的短边消失、自交与反向需拒绝。
- 保温和外包须在接管、检修口处避让；门盖外移时检查连接到内壳的过渡件与贯通孔。不是所有附件都跟外包络移动：按实际连接对象决定归属。
- 原附件中心可能与源开口存在小偏差。对齐实际连接面/轴线并记录修正，不只沿用名义对称坐标。
- 原法兰无孔时允许孔数0；PCD/孔径仅是待启用参数，不能报告为已存在孔。配对接口变化需提示同步对侧，但不修改未授权的源设备。
- 留用孔板或固定附件可能限制参数范围，应在面板说明来源；不能承诺任意缩径。接管外伸长度明确是从内壳、外包还是轴线起算。

## 面板提交与可恢复版本

使用命名参数与原生尺寸方程驱动可保留的特征；孔组重建、跨文件开口或组件变换由脚本同步时，明确实际更新入口。原生旋转特征、脚本切除、固定组件变换与原生配合是不同能力。

面板采用“校验 → 新版本构建 → 几何/干涉检查 → 保存 → 更新当前成功指针”。失败不覆盖上次成功版本。检查孔边距、层间关系、接管承载段及附件碰撞；COM 写入串行，防止重复点击并发更新。后台 helper 隐藏启动，错误和当前版本可见。版本重建会改变组件身份，用户后加的配合/面引用可能需要迁移。

先在独立试件做真实板厚 A→B→A：回读内外解析圆柱面与体积。随后经真实面板控件/按钮验证组合工况、非法输入拒绝和恢复；直接调用底层构建函数不等于面板测试。再测试双击启动器路径、中文目录和本地依赖。

## 体积精度与干涉归因

- 默认积分精度可能造成假体积差。本例采用 SolidWorks GetMassProperties2 的 accuracy=3 与 CadQuery Volume(1e-8) 后消除差异；这些是积分配置，**不是制造公差**。先统一单位、精度和比较对象，再按尺度选绝对/相对容差。
- 即使体积相同，也检查解析面、实际孔中心、PCD、孔数、剖面和流道连通。方位改变用轴线/点与组件变换验证，不能用体积证明旋转。
- 对干涉记录保存组件完整路径、实体身份及相交量。源附件内部已存在的重叠需有基准证据，不能因文件位于 baseline 或显示名称相似就一概忽略。新增的内板/保温/外包/附件交叠单独判定。
- “新增干涉0”不等于“所有干涉0”，保留源重叠数量和说明；零干涉不单独证明制造可行性。

## 本机故障经验与适用边界

|现象|处理与限制|
|---|---|
|布尔工具导入后原 body 引用失效|清选择、重建并重取目标实体；本例逐次 InsertCombineFeature 比批量流程易定位。每步验证结果，不能吞掉失败后仍提交|
|切除工具与某层不相交|先用交集证明无需切除，再清理对应工具；最后以几何/体积验证，不能把任意 COM 失败当作“不相交”|
|方程平方/平方根求值异常|本机平方根用 sqr；带符号项平方曾改为 DX*DX。须读回数值和几何，不推广为全部版本语法限制|
|恢复默认值时异常退出|本例 Windows 事件为 0xc0000374；停用特征副本复用和批量切除后，独立重建通过。只证明替代路径完成，未确定或修复底层根因|
|源304来自缺失的自定义材料库|保留牌号、源库名和材料卡缺失状态。MaterialSpec 不是实体物性卡；不擅用同名/近似牌号替代，不给质量/热工验收结论|

进程退出后先查已保存产物、源哈希和实际进程，任务需要时按主 skill 的有界恢复规则重连，丢弃旧 COM 对象，重新核对文档，不无限重试。
